## What this layer is

Evidence only. Results live in `atypicality_result`, separate from `signal_result`. Phase 5 fusion reads only the six base signals, so these scores never enter risk, the active-signal count or corroboration (gate G6). Tests check this directly: they insert the scores next to the six signals and confirm fusion output is unchanged, and they confirm signal_result rejects them.

Features, per work: `log_amount`, `log_peer_deviation_ratio`, `days_rec_to_sanction`, `days_sanction_to_end_or_age`, `payment_count`, `distinct_payee_count`, `description_length`. Amount, peer ratio, days, counts and description length are log- or log1p-transformed. The peer ratio is Phase 3's own peer median, fed in, not re-derived. MP identity, payee identity and risk score are blocked in code: `assert_no_leakage` raises `LeakageError` on any such column, on every fit and score.

- **Robust Mahalanobis** (primary): sklearn MinCovDet, seed 20260926, on six features: all except `distinct_payee_count` (owner's decision, see below). Stores the distance and each feature's contribution; the contributions sum to the squared distance.
- **Isolation Forest** (comparator): 200 trees, seed 20260926, contamination left at `auto`. Contamination only sets predict()'s inlier/outlier label. That label is never used or stored, so no "flagged %" exists to tune; only the continuous score is kept.
- Both are registered in `model_version`: algorithm, feature-spec hash `59dbbc66929c0527...`, training snapshot, seed, params, metrics and artifact hash.

## Evidence fact: pays the same payee more than once

Why `distinct_payee_count` is not in the Mahalanobis feature set (owner's decision): in the MCD's robust core every work has exactly as many payments as distinct payees. With both counts in, the covariance was singular (condition number about 2e16), and a work paying one payee repeatedly got essentially zero weight in the distance. The robust distance now uses the other six features. Isolation Forest keeps all seven. The repeat-payment pattern is recorded as a plain fact in `work_evidence_fact` (`pays_same_payee_more_than_once`): no score, never read by fusion, the active-signal count or corroboration.

- Scored works with the fact: **16,911** (LS 12,566, RS 4,345).
- Of those, evaluated by the Mahalanobis layer: 12,176. These are the works the singular fit had been blind to.
- Detail stored per work: payment rows, distinct payees, and the most payments to any one payee.
- MCD covariance after the fix: condition number 6.0.

## Limitations

- RS works are unscored because the RS recommended file (Hard Limit 6) doesn't supply a recommendation date, consistent with the existing missing-data policy.
- No labelled outcomes. This layer is evidence for reviewers; whether it is useful is BLUEPRINT §7's reviewer-usefulness check, not shown here. Entry into the risk score needs gate G6.
